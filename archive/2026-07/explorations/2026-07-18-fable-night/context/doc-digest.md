## 1. Product in one paragraph

An **AI-native family co-training coach**: a web app that generates tonight's bodyweight training session for a parent + kids training together on a shared screen (big-screen display + phones as controllers), scaled per member by relative-loading so one session genuinely serves an 8-year-old and an adult at once, capped at 45 minutes, adaptive to who's actually present and how much time is available. It exists to solve three OBSERVED failure modes from the founder's own 16 months of family training: **content exhaustion** (fixed programs run out), **consistency collapse** (rigid programs lose to real life), and **teen drift** (a 14-year-old outgrowing bodyweight-only content wants to train toward something and compete). The engine is a **deterministic constraint-based planner** — no LLM stands between a family and tonight's workout — drawing from a founder-reviewed exercise/block library; LLMs work only at **authoring time** (generating library candidates the founder approves in batches) and in the **coach's voice layer** (templated lines + async artifacts, never live in-session). Determinism is preserved exactly where comparability matters: monthly **Trials** (fixed 5-test benchmark battery), **Challenges** (earned max-effort events, likely renamed "The Crucible"), and fixed **skill progressions** (pull-up, muscle-up, handstand push-up, pistol squat, front lever) stay sacred and never vary. Brand/distribution lead with an authentic father-son story into intentional-father and church communities; the product schema itself is parent-child-generic (no gender field). The plan is solo-founder-executed with AI agents building between founder judgment sessions, gated by numeric validation starting with the founder's own family this summer (Phase 0), then 10-15 beta families (Phase 1), then public launch (Phase 2), with family-vs-family competition and runtime-LLM planning deferred to Phase 3.

### docs/decisions/adr-002-engine-architecture.md
**Accepted 2026-07-06** (retro-recorded as ADR 2026-07-16). The engine-architecture decision in one page: deterministic seeded planner assembles sessions from a founder-reviewed library; LLMs work only offline at authoring time (candidate generation, founder-approved) and in the voice layer (Tier 1 templated/slot-filled at runtime, Tier 2 async artifacts, never live in-session/never chat). ## 3. AI/LLM surface inventory (exhaustive)

The governing hard rule, stated identically across CLAUDE.md, PLAN.md, and ADR-002: **"No runtime LLM in the workout loop in v1."** ADR-002's exact wording: *"no LLM call stands between a family and tonight's workout."* PLAN.md's vision-level version: *"No AI improvisation stands between a family and a workout."*

Every place AI/LLM appears in the current plan:

**1. Authoring-time exercise/block library generation** — governed by `docs/design/library-authoring-pipeline.md` (whole doc) + PLAN.md §Approach-1/§Key decisions + ADR-002. **What it does:** an LLM drafts batches of candidate exercises and blocks (movement variants with full planner metadata — pattern tag, equipment, swap-chain position, time-model params, safety notes) from a "gap brief" sourced from the planner's own library-gap signals. **Deterministic vs. LLM:** generation is LLM; everything downstream (schema/coherence/duplicate/lint/simulation-smoke triage, and the planner's actual selection at runtime) is deterministic code. **Constraints:** *"nothing enters the library without founder approval (PLAN.md hard rule)"* — literally every candidate is reviewed by the founder before merge; auto-triage kills 30-50% pre-review so founder time is spent on judgment, not garbage; keep-rate outside 30-85% halts the queue. Safety-critical content (Tier 1a lines, skill-rung safety_note fields) is explicitly **hand lane only** — the LLM never drafts it, per `library-authoring-pipeline.md §1`.

**2. Coach voice — Tier 1 (templated, in-session, offline-safe)** — governed by `coach-voice.md §6`. **What it does:** covers all in-session moments (session open, mid-set cues, PB lines, missed-week returns, Pact lines, Trials announcements, skill unlocks, teen moments). **Deterministic vs. LLM:** the LLM only drafts candidate line variants in batches at *authoring time*; the founder approves every line before it enters the library; *runtime* behavior is pure slot-fill (`{name}`, `{reps}`, `{prev_best}`) plus deterministic selection rules (rotation, age-band register) — "Zero LLM calls, zero network, unit-testable" at runtime.

**2a. Coach voice — Tier 1a (safety lines)** — a hand-authored subset of Tier 1. **Never LLM-drafted, never rotated, never reworded, ever.** Explicit quote: *"Safety lines are hand-authored only — never LLM-generated, never paraphrased, never A/B tested for voice."*

**3. Coach voice — Tier 2 (async artifacts, online, non-blocking)** — governed by `coach-voice.md §6`. **What it does:** generates the Trials Report narration, week recaps, and Record Book milestone blurbs — always *after* the event, never live. **Deterministic vs. LLM:** the LLM narrates from a structured facts payload the engine emits ("may add zero facts"); output passes mechanical validation before display — every number must appear in the input facts, banned-topic lexicon lint, sibling-ordering check, per-member coverage check — and falls back to a templated skeleton report on validation failure or if offline. Fact-traceability is enforced mechanically, not just by review.

**4. Coach voice — Tier 3 (live conversational coach)** — **explicitly does not exist in v1.** Quote: *"Not a gap — a guardrail... and an offline guarantee. Revisit no earlier than the Phase 3 runtime-LLM upgrade, and only with the teen-companion review done."* No chat surface exists anywhere in the current plan.

**5. Adaptive engine (capability tracking, targets, advancement suggestions)** — governed by `adaptive-engine.md` (whole doc). **Explicitly NOT LLM/ML in v1.** Quote: *"v1 (this doc): pure deterministic functions... Zero ML, zero runtime LLM, fully unit-testable."* Every parameter lives in a founder-editable config table. **Phase 3 note:** the doc explicitly reserves the *possibility* that "learned response models or runtime-LLM planning may replace the internals" behind the same three function signatures — but binds any such future implementation to an inviolable interface invariant: *"an implementation that cannot emit a valid, fact-traceable Reason record does not ship. Explainability is an interface invariant, not a v1 courtesy."*

**6. The session planner itself** — governed by `session-planner-spec.md` and `engine-data-model.md`. **Fully deterministic, never LLM.** CONTEXT.md's own definition of "Planner": *"The deterministic session generator: same inputs and seed, same session. Operates inside hard constraints; never improvises."* `_Avoid_: AI (in specs), generator.`

**7. Phase 3 runtime LLM session generation** — the one place runtime LLM generation is explicitly planned, and explicitly fenced out of Phases 0-2. Roadmap: *"Runtime LLM session generation (premium adaptivity) on top of the proven planner + eval harness."* PLAN.md §Out of scope lists "runtime LLM session generation" among the fences that hold through Phase 2. ADR-002 frames this as the reason the ADR "expires by design": runtime generation with a validation layer was considered and rejected for v1 specifically on trust/offline/eval-burden grounds, then "explicitly scheduled as the Phase 3 upgrade behind the same interfaces."

**8. Marketing-copy framing test** — not a product AI feature, but an AI-adjacent open question: PLAN.md §Approach-3 and the roadmap both call for an A/B test of "adaptive coach" vs. "AI coach" recruitment framing in Phase 1, motivated by ADR-002's honesty concern about what "AI-native" should mean to a user given the actual architecture.

**9. Eval/quality infrastructure for LLM outputs** — `library-authoring-pipeline.md §3-4` (triage gauntlet, per-content-type quality checklists, keep-rate health metric, per-batch acceptance run: property tests + longitudinal simulation + selection-share report + golden-session replay) and `coach-voice.md §6` (moment-map golden lines as the eval bar, Tier 1 batch review loop with an expected keep-rate signal, Tier 2 eval harness with adversarial fixture payloads, "the founder's family is eval zero — if a line lands flat in the garage... it dies, whatever the checklist says").

**Summary of what's deterministic vs. LLM:** the planner, the adaptive engine, the session state machine, and the settlement/scoring logic are 100% deterministic code with zero runtime LLM calls anywhere in v1. The LLM's entire product-facing footprint in v1 is (a) drafting exercise/block/voice-line *candidates* at authoring time, subject to 100% founder review before anything ships, and (b) narrating *already-computed facts* into Trials Reports/recaps after a session ends, subject to mechanical fact-traceability validation. There is no chat surface, no live in-session generation, and no unreviewed LLM output anywhere in the plan.

**Product-level non-negotiables (CLAUDE.md, docs/01, PLAN.md):**
- **45-minute cap is inviolable** — progression through density, never duration (Principle 4; H1).
- **Bodyweight-pure v1** — a pull-up bar is the only equipment, ever, in v1. Weights arrive in Phase 3.
- **No gender in the data model** — role label only (`callSign`: "Dad"/"Mom"/"Coach"); father-son lives in brand/marketing only.
- **No runtime LLM in the workout loop in v1** (ADR-002; see §3 above for full detail).
- **100% founder review** — nothing enters the content library without founder approval, no exceptions, no sampling.
- **COPPA:** under-13s are parent-owned sub-profiles (nickname + birth year only, no login, no contact info); session-scoped controller identity, never credentials; no analytics/persistent identifiers on child-facing surfaces (ADR-003).

- Kebab-case filenames; decisions get a decision-log row the day they're made.

**Numeric gates (roadmap, PLAN.md §Approach-2/4):**
- **Gate 0→1:** 3+ sessions/week × 4+ consecutive weeks, of which ≥2/week are synchronous shared sessions (≥20 min, ≥2 members incl. an adult); attendance-friction ≤20% "pushed" and zero sustained refusal in weeks 3-4; teen ladder views ≥1×/week outside sessions AND ≥1 self-declared rung test per 2 weeks, sustained; plus one deliberately non-synchronous week (no synchronous session required that week; every member ≥2 solo slices; ≥3 covered sessions; Pact machinery holds).

## 5. Vocabulary (CONTEXT.md ubiquitous language)

**People & structure:** Family = the account-holding unit. Member = one person, any age. Sub-profile = an under-13 member (nickname + birth year only). Teen companion = a 13+ member's own-device access (Phase 2). The coach = the product's unnamed voice. Judge = whoever holds the counter during a Trials test (rotates). Squad = 4-6 families sharing a consistency surface (Phase 2).

**Sessions & training:** Session = one planned training event. Roster = who's training tonight. Time dial = declared minutes (15-45). Block = a typed unit of work (straight sets/superset/circuit/AMRAP/for-time). Benchmark block = a block whose exact structure recurs on a schedule so "beat last time" stays honest — the only block-level PB source. Swap = one member substituting an exercise along its chain. Swap chain = the easiest-to-hardest ladder of one movement. Pattern = a movement category the planner balances weekly. Micro-session = under 15 min, still credits the Pact (capped 1/member/day). Slice = one member's scaled solo portion of a shared session. Solo session = planned from scratch for one member (not derived from a miss — that's a slice). The Reveal = the moment tonight's session materializes on the big screen. Tomorrow's Card = a session-close one-tap reserve for next time (⏳). Reset Rep = the short/easy/PB-free session generated after a lapse. Absence Ledger = skip-reason tags the coach visibly learns from. Placement Day = the first family session (bar audit + rung placements for everyone).

**Consistency (the Pact):** Pact = the per-member weekly session commitment, the retention core. Member line = one member's weekly Pact progress. Family ring = the aggregate Pact surface (complete when every member line completes). Streak = consecutive complete family weeks (resets without shame). Covered session = a planned session where every intended participant completed their portion (sync or by slice). Grace weekend = the weekend after Trials week when a missed Trials still counts, flagged "late" (⏳).

**Benchmarks & scoring:** Trials = the fixed monthly 5-test battery, sacred, splittable across ≤3 sessions. Calibration Trials = a family's first Trials (baseline only, mints no PP). Challenge = an earned max-effort event unlocked by 6 sessions (pending rename to **The Crucible** ⏳). Co-op Challenge = one shared work pool the whole family burns down together. Capacity = the absolute universal per-test tier axis, never age-adjusted. Tier = Rookie→Trainee→Skilled→Advanced→Elite→Champion, fixed forever. Progress Points (PP) = the improvement axis and family headline, minted on all-time bests/rung unlocks (⏳ table shape). All-time best = a member's best-ever result (the only PP baseline). PB Watch = the shared-screen state entered within 90% of a relevant all-time best (age-gated: under-11 private by default). Trials Report = the coach-written monthly artifact. Highlighted moment = the report's one featured story (⏳ selection heuristic). Record Book = the permanent family ledger; writing to it is "the Chalking." Torch Board = record lineage inside the Record Book (current/past holders, "torch pass" when a kid out-does a parent).

**Skills:** Skill path = a named progression (Pull-Up, Muscle-Up, HSPU, Pistol Squat, Front Lever). Rung = one stage with a binary parent-judgeable standard, fixed forever, ladders extend upward only. Rung test = a declared, witnessed, one-attempt-per-declaration test. Witness = the parent who validates a rung test. Gap meter = the always-visible distance to the next rung's standard. Earned third slot = a third active skill path, unlocked by standard for anyone (⏳). Park-bar rung = a rung requiring a full-height bar, framed as an outing.

**Surfaces & engine:** Big screen = the shared family display, never touched mid-workout. Controller = a member's phone joined by room code, optimistic, never required. Room code = the session-scoped join code — no credentials ever live on a kid's device. Log strip = the single-device degraded-mode logging affordance (must stay first-class). Planner = the deterministic session generator (never improvises; avoid "AI"/"generator" in specs). Capability state = the coach's memory of one member on one pattern, updated only from logged training. Library = the founder-approved content the planner draws from.
