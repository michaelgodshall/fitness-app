VERDICT: REVISE

The vision contains two direct Phase 2 runtime-LLM fence violations, one additional unacknowledged runtime influence on session generation, material COPPA boundary-blurring, and a Phase 0/1 portfolio that is not honest about a solo founder's critical path or implementation cost. Its strongest architectural idea—the one-way ledger—can survive, but the phase map, self-audit, effort labels, and showcase language need substantial correction.

1. **Severity: Critical**
   - **Location:** `ai-system-vision.md` §1 “Executive summary,” move 5; §4 “Phase 2 — reach and the first runtime surfaces,” “NL request parser”; §7 “A1. Natural-language pre-session request parsing.”
   - **Problem:** The vision schedules an LLM that parses a family's request before planning, emits deltas that change the plan, and asks the founder to approve that as a Phase 2 amendment now. Its defense is that this happens “before planning,” not in the timer loop. That narrows the governing fence beyond recognition. `PLAN.md` §“Key decisions & tradeoffs” says, “**No LLM call between the family and tonight's workout**,” and says runtime LLM generation is an explicit Phase 3 upgrade. `PLAN.md` §“Out of scope (through Phase 2)” also excludes “runtime LLM session generation.” The parser is literally an LLM call between the family and tonight's Session, and its output influences that Session. The chips fallback mitigates network failure; it does not make the primary path fence-compliant. Calling this item **S** also omits the typed parser, confirmation UX, offline floor, evals, telemetry, and safety work.
   - **Suggested fix:** Keep deterministic constraint chips through Phase 2. Move natural-language parsing to Phase 3 and make it conditional on a formal governing-doc amendment at the Phase 3 gate, not a pre-approval in this vision. Re-estimate it as a standalone large workstream if it is ever authorized.

2. **Severity: Critical**
   - **Location:** `ai-system-vision.md` §1 “Executive summary,” move 5 (“shadow-mode LLM planner (P2, fence-clean)”); §4 “Phase 2,” “Shadow LLM planner”; §“Fence-compliance check.”
   - **Problem:** A Phase 2 LLM that generates declarative plans in shadow is still runtime LLM session generation. `PLAN.md` §“Approach,” item 6 assigns “Runtime LLM session generation” to Phase 3, while `PLAN.md` §“Out of scope (through Phase 2)” excludes it explicitly. The vision internally contradicts itself: §1 calls the shadow planner “fence-clean”; the Phase 2 row admits it “brushes the letter”; and the fence check finally concedes that “it *is* an LLM generating sessions at runtime during Phase 2.” This is not a low-stakes founder nod. It changes a locked phase fence that `CLAUDE.md` §“Hard rules” says must hold through Phase 2.
   - **Suggested fix:** Move shadow generation to Phase 3. Phase 2 may prepare a replay corpus, proof-record schema, deterministic baselines, and scoring harness without running an LLM planner. Remove “fence-clean” and the green compliance implication.

3. **Severity: High**
   - **Location:** `ai-system-vision.md` §4 “Phase 2,” “Weight-nudge personalization”; §7 opening claim that only four named items touch a fence; §“Fence-compliance check.”
   - **Problem:** The vision proposes an LLM that tunes each family's planner weights in Phase 2. Those weights influence which otherwise-valid blocks the Planner selects, so model output participates in session generation even if H1–H11 remain intact. This is governed by the same `PLAN.md` passages that keep runtime LLM session generation in Phase 3 and out of scope through Phase 2. Unlike the parser and shadow planner, the vision does not even classify this as an amendment; §7 says everything else fits the fences. The omission makes the self-audit incomplete.
   - **Suggested fix:** Through Phase 2, use founder-reviewed, versioned deterministic parameter snapshots derived by ordinary statistical code. Move any LLM-selected or LLM-tuned planner parameters to the Phase 3 runtime-LLM decision, and list the proposal explicitly as a fence contact.

4. **Severity: High**
   - **Location:** `ai-system-vision.md` §4 “Phase 2,” “The Archivist”; §7 “A2. The Archivist”; §9 founder question 2.
   - **Problem:** The vision recommends a free-text, parent-facing Q&A surface in public v1 and treats “never reachable from a controller” as enough to preserve the chat fence. This is fence-blurring even if the access control works and no minor sees it. `coach-voice.md` §5 “COPPA-adjacent content rules” says “**V1 coach is broadcast-only — there is no chat surface**,” and §6 “Three tiers” says “**Tier 3 — live conversational coach: does not exist in v1**” and may be revisited no earlier than Phase 3. The target itself calls the Archivist “the product's first free-text LLM surface” and admits the first exception weakens the absolute boundary. A routing rule changes “no chat surface” into “chat exists but is intended for adults”; that is a governing-doc amendment, not compliance with the current architecture.
   - **Suggested fix:** Defer the Archivist to Phase 3. If it is later retained as a non-coach parent administration tool, first amend the governing docs explicitly and require a proven access boundary, refusal suite, deletion behavior, and parent-only information model.

5. **Severity: High**
   - **Location:** `ai-system-vision.md` §4 “Phase 1,” “Intake: form + `FamilyProfile` + confirmation cards.”
   - **Problem:** The intake row says confirmation UX “doubles as the COPPA consent gate” and introduces a “small temperament-flag enum” without saying that the flag is forbidden on an under-13 member. `CLAUDE.md` §“Hard rules” restricts under-13 sub-profiles to “nickname + birth year only, no login, verifiable consent.” `coach-voice.md` §5 “COPPA-adjacent content rules” restates “nickname + birth year, nothing else.” `PLAN.md` §“Approach,” Phase 1 defines a much larger compliance gate: data map, vendor DPA checklist, controller analytics policy, parent review/delete flows, and counsel or safe-harbor review. A confirmation card is at most one consent-flow step; it cannot “double as” that gate. As written, the temperament enum also authorizes an extra child-associated profile attribute.
   - **Suggested fix:** State that no temperament or interview-derived attribute may attach to an under-13 sub-profile; use Session inputs or parent/family-level settings only where the data map permits them. Rename confirmation cards as one UX component of the compliance program, never the consent gate itself, and preserve every Phase 1 compliance deliverable in `PLAN.md`.

6. **Severity: High**
   - **Location:** `ai-system-vision.md` §4 “v1 / Phase 0 — rides the existing build”; §5 “Demo assets to build”; §8 “Build-on-ramp — three work items that displace nothing.”
   - **Problem:** The vision pulls a generalized `@coach/evals` package, policy-kernel architecture, expanded future-model telemetry, opportunistic per-rep timestamps, Prep-Pack automation, pre-rendered audio, and shareable case-study scaffolding into Phase 0 while claiming they cost “hours, not sessions” and “displace nothing.” The governing implementation posture is deliberately smaller. `PLAN.md` §“Approach,” Gate 0→1 requires the paper-session kill-switch “before UI investment.” `docs/design/library-authoring-pipeline.md` §5 “Tooling: simplest thing that works, phased” specifies Phase 0 as “repo files + scripts + PR review (build ~0 new surface)” and says building anything more before the paper-session kill-switch clears “would be scope creep.” `PLAN.md` §“Approach,” Phase 0 also puts coach voice beyond templates on the cut list, while `coach-voice.md` §“Open questions for the founder,” question 2 still assumes text and leaves audio undecided. The showcase is driving architecture and media work ahead of the family proof.
   - **Suggested fix:** Before the paper-session test, build only the Planner/data-model slice, founder-reviewed seed Library, and the minimum scripts needed to generate and inspect paper Sessions. Defer Prep-Pack, audio, generic package boundaries, rep-timestamp speculation, and case-study assets until the paper test passes. Preserve only fields demonstrably required by Phase 0 product behavior.

7. **Severity: High**
   - **Location:** `ai-system-vision.md` §4 “v1 / Phase 0” versus §8 “Build-on-ramp” and its closing paragraph.
   - **Problem:** Phase 0 scope is internally inconsistent. The Phase 0 table lists six feature rows, including Canon rules, expanded telemetry, Prep-Pack, and audio. §8 then says the Phase 0 AI surface is exactly what `PLAN.md` already specifies “plus the three seams above,” and says “Everything else in §4 waits its phase.” Pre-rendered audio is neither in `PLAN.md` nor one of those three seams; the Phase 0 table also contains more than the three on-ramp items. This bookkeeping makes additions disappear rhetorically instead of exposing a real delta against the kill-switch path.
   - **Suggested fix:** Replace both sections with one authoritative Phase 0 delta list. For every item, state whether it is required before the paper test, after the paper test but before family Session zero, or after Gate 0→1. Anything not required for the next gate belongs in a later backlog.

8. **Severity: High**
   - **Location:** `ai-system-vision.md` §1 move 1 (“Every later AI surface becomes cheap”); §4 “Phase 1 — the artifact spine + the factory closes its loop”; §8 memory-seam proposal.
   - **Problem:** The vision uses a large speculative Phase 1 portfolio to justify Phase 0 abstraction work. Phase 1 adds a weekly digest, per-session recap, annual letter, certificate, decision ledger, Scouting Report, Torch prophecy, agent factory, coverage cartography, three founder-copilot tools, new intake model, chips, and scheduled model drift runs. `PLAN.md` §“Approach,” Phase 1 already has a full locked path: accounts/family model, the COPPA gate, youth-S&C sign-off, Trials, Challenges, onboarding, coach voice v1, both-parent **monthly** recap, beta recruitment, and acquisition tests. `PLAN.md` §“Working model” gives the founder only 8–10 protected hours per week, and Gate 1→2 is retention/payment evidence, not artifact breadth. Designing Phase 0 around this portfolio risks exactly the future-proofing detour the paper-session gate is meant to prevent.
   - **Suggested fix:** Reduce Phase 1 AI work to the required coach-voice pipeline and the already-governed Trials/monthly recap artifact. Put all other artifacts and ops tools behind Gate 0→1 or demonstrated manual pain. Do not require Phase 0 types to anticipate consumers that have not earned a phase slot.

9. **Severity: High**
   - **Location:** `ai-system-vision.md` §4 effort table: “NL request parser” (**S**), “The Archivist” (**M**), “Agent factory, full roster” (**M**), “Coverage cartography” (**M**), and “Founder copilot cohort tools” (**M**).
   - **Problem:** These labels are not credible for a solo founder. The parser includes runtime-model infrastructure, schema-constrained parsing, confirmation UX, an offline fallback, evals, and a new safety boundary. The Archivist includes authenticated RAG, citation guarantees, prompt-injection/jailbreak defenses, COPPA/security review, and deletion semantics. The agent factory includes Actions crons, a Convex sensor, a learned Critic, multiple isolated critique passes, evidence citations, and review-card integration. Coverage cartography adds state-space simulation, heatmaps, and an optimization loop. “Founder copilot cohort tools” bundles three separate products. `docs/design/library-authoring-pipeline.md` §5 deliberately allows only one thin review route in Phase 1 and defers gap dashboards/analytics/recall tooling to Phase 2+ “only if beta demand forces it.” Its §2 “Batch sizing and throughput math” and `PLAN.md` §“Working model” both budget against 8–10 founder hours, not against unlimited agent output. These rows are **L**, or collections of multiple M/L workstreams.
   - **Suggested fix:** Re-estimate end-to-end cost, including product specification, privacy/security review, fixtures, failure UX, observability, founder acceptance, and maintenance. Split every bundled row into tracer-bullet deliverables. Default to manual scripts and reports until measured founder time justifies automation.

10. **Severity: Medium**
   - **Location:** `ai-system-vision.md` §1 (“provably cannot lie to a child”); §5 showcase item 2, “The Coach That Cannot Lie.”
   - **Problem:** The guarantee is broader than the actual mechanism. `coach-voice.md` §2 “Knowing the family” requires every number to be traceable and bans fabricated observations. Its §6 Tier 2 validator checks that numbers occur in the facts payload, plus banned topics, sibling ordering, and member coverage. Those checks do not prove that every qualitative statement, causal implication, date phrasing, or selection is true; nor does scalar provenance prove that the prose cannot mislead. The governing document promises constrained, traceable narration with a fallback—not a proof that the system cannot lie.
   - **Suggested fix:** Rename the showcase to something accurate, such as “Fact-Traceable Coach Narration,” and claim “every scalar is provenance-linked; validation failure falls back deterministically.” Reserve “cannot lie” for a formally specified and tested semantic guarantee, if one ever exists.

11. **Severity: High**
   - **Location:** `ai-system-vision.md` §5 showcase item 3, “Regulation as Engineering”; §6 “The kid-safety eval suite as a differentiator”; §“Fence-compliance check”; §9 founder question 3.
   - **Problem:** “COPPA 2025 as code” and “provable erasure” overstate both scope and readiness. The vision's own fence check admits that the delete-versus-append-only specification is unwritten, and founder question 3 leaves the choice open. `coach-voice.md` accurately labels its rules “COPPA-adjacent content rules,” not compliance. `PLAN.md` §“Approach,” Phase 1 makes compliance contingent on a complete data map, vendor DPAs, analytics policy, parental review/delete flows, and counsel or safe-harbor review. A lexicon linter and event re-fold test cover only narrow engineering controls; they do not constitute COPPA compliance.
   - **Suggested fix:** Until the Phase 1 compliance gate and deletion design are complete, call this “minor-surface policy automation” and describe erasure as a design target. Publish a COPPA case study only after the full gate, external review, and end-to-end deletion tests pass.

12. **Severity: Medium**
   - **Location:** `ai-system-vision.md` §1 (“Every 2026 fitness app has a chatbot. Almost nobody…”); §6 (“No fitness competitor will have this, most kid-tech companies don't…”); §5 showcase superlatives.
   - **Problem:** These are unverified market-wide claims stated as fact. `PLAN.md` §“Approach,” Phase 1 explicitly schedules incumbent/substitute recon and says competitor teardowns repeat at every phase boundary. The target itself says in §4 “Founder copilot cohort tools” that recon claims remain **REPORTED until verified**. Its executive and showcase copy violates its own evidence label before that recon exists. “Almost nobody,” “no competitor,” “most kid-tech companies,” “best slide,” and “rarest and most billable” are positioning hypotheses, not established 2026 facts.
   - **Suggested fix:** Mark each as a hypothesis and attach a source/evidence date once the scheduled recon is complete. Until then, use bounded language: “designed to differentiate,” “we have not yet found,” and “candidate consulting case study.”

13. **Severity: Medium**
   - **Location:** `ai-system-vision.md` §1 (“Two models … landed on one design — that is evidence, not coincidence”); §1 claim that the stack is “exactly what enterprise clients pay for in 2026.”
   - **Problem:** Two models reading the same source documents are correlated reviewers, not independent market evidence. `PLAN.md` §“Approach,” Gate 0→1 requires repeated family behavior, and Gate 1→2 says willingness to pay is “proven by payment, not interviews.” `PLAN.md` §“Validation gates are numeric and written” exists precisely to prevent persuasive synthesis from substituting for observed behavior. Model convergence may raise confidence in an architecture candidate; it does not validate product demand, consulting demand, safety, or differentiation.
   - **Suggested fix:** Replace “evidence, not coincidence” with “a corroborating design review result.” Treat consulting value as a hypothesis until backed by qualified leads, paid work, or explicit client feedback, using the same numeric discipline as the product gates.

14. **Severity: Low**
   - **Location:** `ai-system-vision.md` §3 (“workout loop”); §4 “Shadow LLM planner”; §7 A1; §“Fence-compliance check”; §4 “Torch Pass Prophecy” (“crosses a parent's record”).
   - **Problem:** The document claims “Terms per `CONTEXT.md`” but repeatedly uses “workout loop” in a technical specification and uses “record” for an individual's best. `CONTEXT.md` §“Sessions & training,” “Session” says “workout” is acceptable in coach speech but “never in specs.” `CONTEXT.md` §“Benchmarks & scoring,” “All-time best” says to avoid “record” for that concept. More importantly, the non-canonical “workout loop” term enables the document to redefine the hard fence as the timer portion only, while `PLAN.md` speaks more broadly about the path between the family and tonight's Session.
   - **Suggested fix:** Use “Session-planning path,” “in-flight Session,” or “Session execution loop” as appropriate, and use “all-time best” for the Torch comparison. Define the runtime boundary once with canonical terms and apply it consistently.

No direct proposal exceeds the 45-minute cap, and the document retains founder A/E/R as the Library minting gate and deterministic offline Tier-1 behavior. Those compliant pieces should remain unchanged while the runtime, COPPA, scope, cost, and claim issues above are revised.
